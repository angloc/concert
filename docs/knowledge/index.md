# Knowledge base

What is true of bide now, and the design that is approved but not yet built.

Provenance: refactored from the repository's own documents on the `legato-experiments` branch at commit `24020e2`: `README.md` (upstream, unchanged since `d581a30`), `film/CAST.md`, `film/WORLD.md` and `docs/register-and-compromise.md` (status "design agreed", dated 2026-11-26). Further decisions were taken from the commit history and from the owner.

* [Architecture](architecture.md) - the modules, what each hides, how a build flows from score to page; read before changing any module
* [Tech stack](tech-stack.md) - languages, runtimes and tools chosen for each component, with the reason
* [Open questions](open-questions.md) - unresolved questions and known risks; read before planning work
* [Platforms](platforms.md) - the delivered file and the browsers it targets
* [Voice model](voice-model.md) - how the physical model of the singing voice works, and the intelligibility evidence for it
* [Singer profile](singer-profile.md) - who is singing, independent of any song: the profile fields that exist, capacity today, personas as overlays
* [Description](description/index.md) - the approved design for describing songs, arrangements, performances, singers and instruments as data, and the score format evidence; not yet built
* [Performance](performance/index.md) - feasibility of a sung performance, compromises, timing, model corrections and listening verdicts
* [Film](film/index.md) - the drawing APIs for people, places, weather and the red thread
